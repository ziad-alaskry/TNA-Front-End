## Executive Summary

This document defines a production-grade Visual Regression Testing (VRT) strategy for the TNA (Temporary National Address) platform — an enterprise-grade multi-role address management system built on **Next.js 14 (App Router)**, **TypeScript**, **Tailwind CSS v3** with a CSS-variable-driven design token system, **Zustand** for state management, and **i18next** with RTL support. The application serves four distinct user roles — **Visitor**, **Owner**, **Carrier**, and **Authority (Gov)** — each with dedicated dashboard layouts, navigation shells, and data streams.

Any pixel-level deviation in layout integrity — especially within role-based dashboards — directly violates the platform's UX standards and risks regulatory compliance. This VRT infrastructure eliminates that risk by capturing deterministic, reproducible snapshots across roles, browsers, and locales, with precise masking of known-volatile UI zones.

### 1.2 Style Infrastructure & Design Token Map

The platform enforces a **CSS-custom-property-driven design system** with three layers of token definition:

| Layer | File | Purpose |
|---|---|---|
| **SPATIAL Base** | `design-assets/design-tokens.json` | Absolute source-of-truth: 388 tokens across color, typography, spacing, border-radius, shadow, border, opacity, icon-size, component, motion, z-index |
| **SPATIAL CSS** | `src/app/tokens.css` | Direct CSS custom-property translation of the JSON (one-to-one mapping) |
| **Global CSS** | `src/app/globals.css` | Augmented with shadcn-compat aliases, sidebar theme, notification system CSS classes, `auth-bg-pattern`, `ui-dark-surface` |
| **Tailwind Config** | `tna-project/tailwind.config.js` | Build-time: maps `colors.*`, `spacing.*`, `borderRadius.*`, `boxShadow.*`, `fontSize.*`, `fontFamily.*`, `height.*`, `transitionDuration.*` to their respective CSS variables via `var(--token-name)` |

**Key token groups relevant to VRT:**

```
Colors: --color-primary (#2196C9), --color-primary-dark (#1565A8), 
        --color-success (#4CAF50), --color-error (#EF4444), 
        --color-surface (#FFFFFF), --color-background (#F3F4F6),
        --color-divider (#D1D5DB)

Typography: --text-xs (11px) → --text-3xl (34px)
            --font-arabic (IBM Plex Sans Arabic), --font-english (Rubik)
            --font-mono (JetBrains Mono)

Spacing: --space-0 (0px) → --space-12 (48px)
         --layout-content-max-width: 960px
         --navbar-height: 83px; --header-height: 44px

Radius: --radius-sm (6px) → --radius-2xl (24px), --radius-full (9999px)

Shadow: --shadow-card (0 4px 6px -1px rgba(0,0,0,0.1))
        --shadow-button (0 4px 12px rgba(37,99,235,0.25))
        --shadow-button-red (0 4px 12px rgba(239,68,68,0.20))

Motion: --duration-fast (150ms) → --duration-normal (250ms)
        --ease-default (cubic-bezier(0.4,0,0.2,1))
```

**VRT Implication:** Because colors, spacing, radius, and shadows are all driven by CSS variables, a single post-production token change (e.g., changing `--color-primary`) will propagate to every component. VRT snapshots will therefore flag all affected components simultaneously — the mechanism functions as a true design-system integrity gate.

### 1.3 Authentication & Session State Architecture

The authentication layer is intentionally **facade-level** — the login page builds a mock user object in-memory, writes it to Zustand's `persist` middleware, and redirects. There is no real backend auth handshake in development.

#### Auth State Flow

```typescript
// src/lib/store/useAuthStore.ts
export const useAuthStore = create<AuthState>()(
  persist(
    (set) => ({
      user: null,
      token: null,
      role: null,
      setAuth: (user, token) => set({ user, token, role: user.user_role }),
      logout: () => set({ user: null, token: null, role: null }),
    }),
    { name: 'auth-storage' }   // ← Zustand persist storage key
  )
);
```

The `persist` middleware serialises the state to `window.localStorage` under the key `auth-storage`. The serialised shape is:

```json
{ "state": { "user": { ... }, "token": "...", "role": "OWNER" }, "version": 1 }
```

#### Programmatic Login Flow (`loginAs(page, role)`)

```typescript
// Derived from: src/lib/types/auth.ts
type UserRole = 'VISITOR' | 'OWNER' | 'CARRIER_STAFF' | 'GOV_USER';

// In tests — the login page calls:
const handleLogin = () => {
  const userRole = roleMap[role] || 'VISITOR';
  const mockUser: User = { user_id: `dev-${role}-1`, ..., user_role: userRole };
  setAuth(mockUser, 'mock-jwt-token-' + role);
  router.push(`/${locale}/${role}/home`);
};
```

**Abstraction:** For VRT we do **not** click through the login UI. Instead, `loginAs()` directly injects the serialised auth state into `localStorage` via `page.evaluate()`, then navigates directly to the role home page. This eliminates UI dependency in the critical VRT path.

#### Already-Implemented Fixture

`tests/e2e/fixtures/auth.fixture.ts` already contains the complete `setAuthState(page, role)` helper. This maps `UserRole` → `StoredAuthState` and injects it as the `auth-storage` localStorage key. The VRT engine will reuse this function.

### 1.4 Volatile UI Zone Inventory

The following components and regions are known to change between runs and **must be excluded from pixel comparison**:

| Zone | Component | Volatility Driver | Mask Selector Strategy |
|---|---|---|---|
| **Hero carousel indicator dots** | `VisitorHomeModule.tsx` | Auto-rotating 5s interval slides — active index shifts | `text=carousel-indicator` class, or mask first `.rounded-full` in carousel |
| **Timestamps** | All dashboards | `new Date(...).toLocaleDateString()` and `toLocaleTimeString()` in mock data | `[data-testid$="-timestamp"]` or `time` / `datetime` elements |
| **Live shipment status badges** | `DataTableLayout.tsx` | List data changes on every load | Entire status-badge column or `[class*="status-"]` |
| **Chart bar heights** | `OwnerHomeModule.tsx` | `mockWeeklyRevenue.map()` — client-side percentage height | `.owner-revenue-chart` class or parent `section` wrapper around chart |
| **TNA code values** | All role homes | `tna_code` is a UUID-like string | `.font-mono` text elements in TNA cards |
| **Star rating / accessibility badges** | `DetailViewLayout.tsx` | Computed from data state | `[data-testid*="badge"]` pattern |
| **Toast notifications** | `ToastProvider` | Ephemeral mount/unmount | `.sonner-toast` or `[role="status"]` |

**Volatile Selector Summary for VRT masks:**

```
CAROUSEL_INDICATORS   → [data-testid="carousel-dot"]
TIMESTAMP_STAMPS      → time, [datetime], [data-testid$="-timestamp"]
REVENUE_CHART         → .revenue-chart, .bar-chart-wrapper
STATUS_BADGES         → [class*="status-badge"], [class*="px-2"][class*="rounded-full"]
TNA_CODE_MONO         → .font-mono.tna-code
TOASTS                → [role="status"], .sonner-toast
```

## Phase 2: Production-Grade Playwright Configuration

### 2.1 `playwright.config.ts` Reference Implementation

```typescript
// tna-project/playwright.config.ts
// VRT Infrastructure — Enterprise Grade
// Single source of truth for ALL visual regression test execution

import { defineConfig, devices } from '@playwright/test';

/**
 * Viewport Constants
 * Deterministic across all roles and browsers.
 * Optimization targets: data-dense dashboard views including stat grids
 * (4-column on desktop), data tables, and sidebars.
 */
const VIEWPORT = {
  width: 1440,
  height: 900,
} as const;

/**
 * Global timeout budget
 * 60s accounts for:
 *   - `npx playwright install` one-time browser binary fetch (CI only)
 *   - Next.js dev server cold-start on first invocation (120s in webServer)
 *   - Multiple role-based auth injections in a single test run
 */
const GLOBAL_TIMEOUT_MS = 60_000;

/**
 * Per-expect timeout
 * Snapshot diff computation on large dashboards can exceed the default 5s
 * when using `maxDiffPixelRatio` and `maxDiffPixels` with anti-aliasing
 * analysis on hiDPI displays.
 */
const EXPECT_TIMEOUT_MS = 10_000;

/**
 * Diff threshold rationale
 * `maxDiffPixelRatio: 0.02`
 *   → Allow ≤ 2% of pixels to differ before flagging a regression.
 *   → Covers anti-aliasing differences across Chrome / Firefox / WebKit
 *     font-rendering engines on different host OS text-expansion metrics.
 *   → Any structural layout anomaly (box shift, overflow, missing element)
 *     will exceed this ratio on a 1440×900 frame (1,296,000 px total;
 *     25,920 px allowed diff ≈ 160×160 region = one entire card rendered
 *     wrong → instantly fails).
 *
 * `maxDiffPixels: 25_920`
 *   → Hard upper bound in pixel count as an additional fail-fast for
 *     absolute coverage (complements the ratio-based threshold).
 */
const DIFF_CONFIG = {
  maxDiffPixelRatio: 0.02,
  maxDiffPixels: 25_920,
} as const;

/**
 * CI vs Local distinction
 * CI: strict mode, 1 worker (no parallelisation → serial snapshot capture),
 *     retries: 1 (transient rendering glitch tolerance).
 * Local: unlimited workers, retries: 0, reuseExistingServer: true.
 */
const isCI = !!process.env.CI;

export default defineConfig({
  /**
   * ── Directory ─────────────────────────────────────────────────
   * VRT specs live alongside E2E specs but under their own directory
   * namespace. Kept separate to allow independent CI flags.
   */
  testDir: './tests/visual',

  /**
   * ── Timeouts ──────────────────────────────────────────────────
   */
  timeout: GLOBAL_TIMEOUT_MS,
  expect: {
    timeout: EXPECT_TIMEOUT_MS,
  },

  /**
   * ── Parallelism ────────────────────────────────────────────────
   */
  fullyParallel: true,
  forbidOnly: isCI,
  retries: isCI ? 1 : 0,
  workers: isCI ? 1 : undefined,             // Serial in CI to avoid contention port noise

  /**
   * ── Reporter ──────────────────────────────────────────────────
   */
  reporter: [
    ['html',    { open: 'never', outputFolder: 'test-results/visual-report' }],
    ['json',    { outputFile: 'test-results/visual-results.json' }],
    ['list'],
  ],

  /**
   * ── Snapshot / Artifact Policy ─────────────────────────────────
   * - `update`: snapshots are always updated when `--update-snapshots` is passed.
   * - `on-first-retry`: trace + screenshot captured on the very first retry
   *   attempt (captures the exact rendered state before the flake).
   *   Second and subsequent retries are not traced to save disk.
   */
  snapshotDir: './tests/visual/snapshots',

  use: {
    baseURL: 'http://localhost:3000',

    /**
     * Screenshot: only on VRT diff failure.
     * The VRT harness calls `expect(page).toHaveScreenshot(...)` internally;
     * this global fallback captures unexpected errors.
     */
    screenshot: 'only-on-failure',

    /** Trace: captured on first failure retry for post-mortem debugging */
    trace: 'on-first-retry',

    /** Video: only captured when a test fails at any retry */
    video: 'retain-on-failure',

    /** Consistent locale cookie for i18n rendering */
    extraHTTPHeaders: {
      'Accept-Language': 'en-US,en;q=0.9',
    },
  },

  /**
   * ── Browser Projects ───────────────────────────────────────────
   * Three desktop browsers — Chromium, Firefox, WebKit.
   * Note: WebKit handles text anti-aliasing differently from Chromium;
   * `maxDiffPixelRatio: 0.02` is calibrated to absorb this variance.
   * If WebKit false-positives become frequent, reduce to 0.015 for that
   * project only (override at project level).
   */
  projects: [
    {
      name: 'chromium-vrt',
      use: {
        ...devices['Desktop Chrome'],
        viewport: VIEWPORT,
      },
    },
    {
      name: 'firefox-vrt',
      use: {
        ...devices['Desktop Firefox'],
        viewport: VIEWPORT,
      },
    },
    {
      name: 'webkit-vrt',
      use: {
        ...devices['Desktop Safari'],
        viewport: VIEWPORT,
      },
      // Tighter tolerance for WebKit's distinct text rendering
      expect: {
        ...DIFF_CONFIG,
        maxDiffPixelRatio: 0.015,
        maxDiffPixels: 19_440,
      },
    },
  ],

  /**
   * ── Dev Server ─────────────────────────────────────────────────
   * Playwright auto-starts `npm run dev` before any test runs and waits
   * until port 3000 responds. `reuseExistingServer` in local mode keeps
   * the developer's long-running dev process rather than forking a new one.
   */
  webServer: {
    command: 'npm run dev',
    port: 3000,
    timeout: 120_000,
    reuseExistingServer: !isCI,
    stdout: 'pipe',
    stderr: 'pipe',
  },
});
```

### 2.2 Design Decisions Rationale

| Decision | Reasoning |
|---|---|
| `maxDiffPixelRatio: 0.02` | Industry standard. Catches real regressions while tolerating sub-pixel OS font rendering noise. Ratio-based rather than absolute pixel count ensures the threshold scales proportionally to viewport size. |
| Separate `tests/visual/` directory | Clean separation from functional E2E specs in `tests/e2e/`. VRT specs are typically long-lived stability guards; functional specs are faster-changing and more volatile — keeping them separate prevents confusion in PR reviews. |
| `snapshotDir` explicit | Default `__snapshots__` collides with E2E test snapshots (which some Playwright versions still emit). Explicit directory makes snapshot review simple. |
| Serial workers (`1`) in CI | VRT snapshots are large bitmaps. Parallel execution multiplies Chrome/WebKit memory requirements and can cause OOM in GitHub Actions runners with 7 GB limits. |
| `expect` timeout: 10s | `toHaveScreenshot()` with `maxDiffPixelRatio` runs pixel-level comparison with sub-pixel anti-aliasing analysis. On a 1440×900 screenshot this adds measurable overhead; 10s prevents flaky timeouts on CI. |
| WebKit ratio: 0.015 | WebKit's Core Text engine renders slightly sharper glyph edges than Chromium's FreeType engine. Calibrated tighter to still catch regressions but not false-positive due to font hinting differences. |
| `trace: 'on-first-retry'` | Retain the exact network log, DOM snapshot, and console output from the **first** failure only — enough for post-mortem. Docs recommended `always` which fills disk rapidly; `on-first-retry` balances informativeness vs. cost. |

```typescript
 * Injects the Zustand persist storage payload directly into localStorage.
 * Call this before navigating to any role-protected page.
 */
export async function loginAs(page: Page, role: UserRole): Promise<void> {
  const authState = mockAuthStates[role];
  const storageData = JSON.stringify({
    state: authState,
    version: 1,
  });

  // Navigate to `/` first to establish a simple, clean document context
  await page.goto('/');
  await page.evaluate(
    ({ key, data }: { key: string; data: string }) => {
      localStorage.setItem(key, data);
      try { sessionStorage.setItem(key, data); } catch (_e) { /* SSR guard */ }
    },
    { key: AUTH_STORAGE_KEY, data: storageData }
  );
}
```

### 3.3 Snapshot Strategy & Mask Taxonomy

The masking approach follows a **defensive, layered strategy**:

```
Layer 1 — Semantic data attributes   (preferred)
  [data-testid="carousel-dot"]
  [data-testid="revenue-chart"]
  [data-testid$="-kpi-value"]

Layer 2 — Semantic HTML elements     (when data-testid absent)
  time  /  [datetime]
  [role="status"]   (toast / alert semantics)

Layer 3 — CSS class patterns         (last resort)
  [class*="status-badge"]
  [class*="rounded-full"][class*="px-2"]

Layer 4 — Non-semantic file paths    (internationalisation / logo)
  img[src*="/brand/"]
  img[src*="/locales/"]
```

When the relevant `data-testid` attributes do not yet exist (as is the case today), masks use the **closest available Layer 2+ selector** — no masking is skipped. The Phase 3 targeted snapshot sections (e.g., `await expect(page.getByTestId(...))`) are **future enhancement slots**: they become active in a follow-up pass once `data-testid` attributes are added to the volatile components in the actual source code by the feature team.

**Mask exception policy:** If a mask selector matches more than 15 elements, it must be narrowed. Masking 100+ elements can introduce unintended layout comparisons under masked boundaries. In those cases, the masking should instead target the **container** level (e.g., mask the section wrapper, not each individual badge).

## Phase 4: Deterministic Orchestration — Local & CI

### 4.1 Docker Execution Command

```bash
# Run VRT suite using Playwright's official Firefox-only Linux image.
# Ensures exact browser binary versions are locked (no host-OS drift).
# HOST_OS controls FONTS, display server, and sub-pixel rendering → snapshots
# are therefore built on Linux, matching CI behaviour.

docker run \
  --rm \
  --network host \
  --shm-size 4gb \
  -v "${PWD}:/workdir" \
  -w /workdir/tna-project \
  mcr.microsoft.com/playwright:v1.60.0-jammy \
  bash -lc "
    npm ci --ignore-scripts                 # Install deps, skip postinstall
    npx playwright install chromium         # Install only needed browsers
    npx playwright install firefox
    npx playwright install webkit
    npx playwright test --update-snapshots  # Capture authoritative VRT baselines
  "
```

**Parameter rationale:**

| Flag | Purpose |
|---|---|
| `--network host` | Required so the Playwright Docker container can reach `localhost:3000` running on the host. For CI, remove this and use `--add-host=host.docker.internal:host-gateway` instead. |
| `--shm-size 4gb` | Browsers are Chrome-class processes; `/dev/shm` defaults to 64 MB in Docker, causing render hangs. 4 GB is the recommended minimum. |
| `--v "${PWD}:/workdir"` | Mounts the project root. Snapshots are written back to the host filesystem. |
| `v1.60.0-jammy` | Ubuntu 22.04 with Playwright 1.60.0 pre-installed. Pinning both major and minor version eliminates binary drift. |
| `npm ci --ignore-scripts` | Deterministic install from `package-lock.json`. Skips `postinstall` hooks that may attempt browser auto-installation. |
| `npx playwright install <browser>` | Explicitly installs only the three browsers needed, further reducing container image overhead. |
| `--update-snapshots` | **This is the authoritative snapshot rewrite command.** All existing VRT baselines are replaced. Run this locally, review `git diff`, then commit to git. |

**GitHub Actions CI snippet:**

