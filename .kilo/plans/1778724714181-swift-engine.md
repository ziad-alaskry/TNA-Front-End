## 2. Fix Strategy — Adjusted for Current Architecture

### Fix A: Mobile Overlay & Positioning

**Target:** `AppShell.tsx` lines 95–131

**Current problem:** Mobile sidebar uses `absolute` positioning inside a `fixed` wrapper. The drawer doesn't cover full viewport height. Z-index is flat at `z-50`, which conflicts with multiple other elements (BottomNav, Modals, sticky headers — see Risk R1). Body scroll is not locked.

**Adjusted strategy:**
1. Mobile wrapper: **change** `z-50` to `z-[51]` to sit above all existing `z-50` elements
2. Overlay element: `absolute inset-0 z-[50]` with `bg-black/35` (no blur), `transition-opacity duration-300`, pointer-events controlled by visibility state
3. Drawer `<aside>`: change from `absolute inset-y-0` to `fixed top-0 bottom-0 z-[52]` with width `w-72`, RTL-aware horizontal position (`right-0` for RTL, `left-0` for LTR)
4. Slide animation: `transform: translateX(100%)` (RTL: from right) closed, `translateX(0)` open, with `transition-transform duration-300 ease-out`
5. Body scroll lock: guarded `useEffect` — only fires when `!isDesktop` and `sidebarOpen` changes; cleanup on unmount (see Risk R3)

**Architecture note:** The drawer must sit above the overlay in z-index (300 vs 299). Clicking the overlay closes the drawer. The header (z-[var(--z-header)]) remains visible above both.

### Fix B: Remove Backdrop Blur

**Target:** `AppShell.tsx` line 102

**Current problem:** `backdrop-blur-sm` on the overlay element causes performance issues on low-end devices.

**Adjusted strategy:**
1. Remove `backdrop-blur-sm` entirely from the overlay className
2. Replace with plain semi-transparent background: `bg-black/35` (already using `bg-primary-dark/60` — adjust to `bg-black/35` for consistency with design tokens)
3. Add `transition-opacity duration-300` for smooth fade
4. Control visibility via opacity: `opacity-100` when open, `opacity-0` when closed
5. Set `pointer-events-none` when not visible to prevent click-through

**No architecture impact.** Purely visual/performance change.

### Fix C: Mobile Sidebar Background to White

**Target:** `AppShell.tsx` line 111, `RoleSidebar.tsx` line 115–134

**Current problem:** Mobile drawer uses `bg-primary-gradient` instead of white. The sidebar header (brand + role badge) has its own gradient that should be preserved.

**Adjusted strategy:**
1. `AppShell.tsx:111` — Change `bg-primary-gradient` to `bg-white` on the mobile `<aside>` drawer
2. `RoleSidebar.tsx:115-134` — The sidebar header block (TNA logo + role badge) retains its brand gradient as a **contained strip** at the top of the sidebar
3. Ensure no modifier class or open-state override applies a gradient to the drawer root
4. The collapsed state on desktop should not trigger the header gradient (already handled by `!collapsed` condition)

**Design consistency:** Desktop sidebar already uses white background. Mobile sidebar should match. Only the top ~60px strip within the sidebar content area shows the brand gradient.

### Fix D: Remove User Profile Component

**Target:** `RoleSidebar.tsx` lines 36–57 and line 137

**Current problem:** `<SidebarProfile>` renders avatar, user name, and balance/role badge inside the sidebar body. This is redundant — the header already shows user identity, and the topbar avatar provides access.

**Adjusted strategy:**
1. **Delete** the entire `SidebarProfile` component definition (lines 36–57)
2. **Delete** the render call `<SidebarProfile role={role} />` (line 137)
3. Remove unused imports: `UserAvatar`, `useWallet`, `useAuthStore` (if no longer needed by SidebarProfile — verify before removing; `useAuthStore` is still needed for the sign-out button)
4. Retain all role-based navigation logic — only the standalone profile display block is removed

**Architecture note:** The user's avatar and name remain visible in the topbar `Header.tsx` (lines 126–138). This is intentional and sufficient for identity display.

### Fix E: Remove Sidebar Scrollbar

**Target:** `RoleSidebar.tsx` line 141, `AppShell.tsx` line 78

**Current problem:** `overflow-y-auto` on nav containers creates visible scrollbars when content overflows.

**Adjusted strategy:**
1. `RoleSidebar.tsx:141` — Change `overflow-y-auto` to `overflow-hidden` on the nav element
2. `AppShell.tsx:78` — Desktop sidebar nav already uses `overflow-y-auto` with `no-scrollbar` class. Change to `overflow-hidden` for consistency
3. **Role item budgeting** to ensure all nav items fit within viewport without scroll:
   - Visitor: 5 items → fits comfortably with standard spacing (`px-3`, `gap-1`)
   - Owner: 4 items → fits comfortably
   - Carrier: 7 items → use compact spacing (`gap-1.5`, `py-2`)
   - Gov: 8 items → use compact spacing (`gap-1.5`, `py-1.5`)
4. Implement **conditional compact class**: when `role === 'Gov' || role === 'Carrier'`, apply reduced padding (`py-2 px-3`) and tighter gap (`gap-1`). See Risk R4 for fallback if this still overflows.
5. Test on 768px viewport height (shortest common desktop height) to confirm no overflow

**Removed fallback note** (was: "reduce top/bottom padding from `py-8` to `py-4`"). The nav container padding in `RoleSidebar.tsx` is already `py-8` via `px-3`/`py-2.5` on individual items, not a top-level `py-8`. The actual fix is the conditional compact class above.

### Fix F: Replace Support Footer with Sign-Out Button

**Target:** `RoleSidebar.tsx` lines 177–190

**Current problem:** The support footer displays "الدعم / Support" with `logged_in_as` text that exposes raw i18n keys and provides no useful action.

**Adjusted strategy:**
1. **Delete** the entire support/support footer block (lines 177–190)
2. **Add** a new sign-out button footer section:
   - Container: `p-3 border-t border-[var(--divider)]` (divider color from design tokens)
   - Button styling: `flex items-center gap-3 px-3 py-2.5 text-sm font-medium text-[#d94f4f] hover:bg-[#fdf0f0] rounded-md transition-colors`
   - Icon: `ArrowRightFromBracket` (Phosphor Icons), size 22, red color
   - Label: `{t('common.signOut')}` → "تسجيل الخروج" (AR) / "Sign Out" (EN)
   - Collapsed state: icon only, with `sr-only` span for accessibility
   - On click: `useAuthStore.getState().logout()` + redirect to `/{locale}/visitor/home`
3. Import `ArrowRightFromBracket` from `@phosphor-icons/react`
4. Import `useAuthStore` (already available in RoleSidebar if SidebarProfile was using it)
5. Add `useRouter` from `next/navigation` for post-logout redirect

**i18n additions required:**
- `ar.json`: `"common": { "signOut": "تسجيل الخروج" }`
- `en.json`: `"common": { "signOut": "Sign Out" }`

## 7. Risk Mitigation — Resolved

| # | Risk | Likelihood | Resolution |
|---|------|-----------|------------|
| R1 | **Z-index conflicts** — Current sidebar uses `z-50`, which is shared by BottomNav (`BottomNav.tsx:87`), ModalOverlay (`ModalOverlay.tsx:82`), sticky headers, and checkout modals. Overlap is guaranteed. | **High** | Sidebar mobile wrapper changes from `z-50` to `z-[51]`. Overlay set to `z-[50]`. Drawer `<aside>` set to `z-[52]`. This places the drawer above all existing `z-50` elements without disrupting their stacking contexts. For desktop sidebar (`AppShell.tsx:73`), keep existing `z-[40]` since it's inside the flex layout flow, not a stacking conflict. |
| R2 | **Orphaned imports after deleting SidebarProfile** — `useWallet` and `UserAvatar` are only used inside `SidebarProfile`. Deleting the component leaves dead imports that may break lint/build. | **High** | After deleting `SidebarProfile` (lines 36–57) and its render call (line 137), also remove: `import { useWallet } from '@/lib/hooks/useWallet'` (line 27) and `import { UserAvatar } from '@/components/ui/UserAvatar'` (line 28). Keep `useAuthStore` (line 26) — it is still needed for the sign-out button. Verify no other usage of `useWallet`/`UserAvatar` exists in this file before removal. |
| R3 | **Body scroll lock fires on desktop** — `sidebarOpen` state exists regardless of viewport. If the useEffect is not guarded, scroll lock could trigger on desktop when sidebar is in a transitional state. | **Medium** | Guard the useEffect: `useEffect(() => { if (isDesktop) return; document.body.style.overflow = sidebarOpen ? 'hidden' : ''; return () => { document.body.style.overflow = ''; } }, [sidebarOpen, isDesktop])`. This ensures scroll lock only activates on mobile viewports. |
| R4 | **Nav items overflow for Carrier (7) and Gov (8)** — With header block (~60px) + sign-out footer (~48px) + nav padding, the available nav height on a 768px viewport is ~600px. At standard spacing (12px padding, 48px/item, 4px gap), 8 items need ~424px. Fits, but margin is thin. | **Medium** | Apply conditional compact spacing: add a `compact` class when `role === 'Gov' || role === 'Carrier'` that reduces nav padding to `py-2 px-3` and gap to `gap-1`. If overflow is still detected in testing, further reduce to `gap-0.5` and `py-1.5`. Test on 768px viewport height as gate. |
| R5 | **i18n key mismatch between AR/EN** — Adding `signOut` to only one locale file causes silent fallback to key string. | **Low** | Add both keys in the same commit. Verify by running the app's i18n lint/health check if available. No dependency between the two files. |
| R6 | **Layout shift when mobile sidebar opens** — Body scroll lock + overlay appearance could cause a visual jump if the page was scrolled. | **Low** | The overlay is `position: fixed` so it doesn't affect document flow. Body scroll lock preserves scroll position. No layout shift expected. Verify by testing with a scrolled page before opening the drawer. |
| R7 | **Post-logout redirect goes to wrong locale** — After `logout()`, the user state is cleared before redirect fires, potentially losing the locale context. | **Low** | Call `router.push('/' + locale + '/visitor/home')` immediately after `logout()` within the same synchronous handler. The locale is read from the i18n context which persists until the component unmounts — before the auth store clears it. |
