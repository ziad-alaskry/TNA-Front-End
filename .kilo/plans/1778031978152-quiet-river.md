### 3.2 Workflow Implementation

#### Flow 1: Binding Activation with Mandatory Payment
**Blueprint Sequence:**
1. Trigger: Visitor confirms binding on NA variant
2. State: Backend creates `bindings` (PENDING) + `rent_contracts`
3. Financial Gate: Redirect to payment `POST /v1/orders/{id}/pay`
4. Verification: Poll `financial_transactions.status` - BLOCK if != PAID
5. Activation: Update `bindings.status` to ACTIVE

**Current Implementation:**
- `BindingContext.tsx`: Has `acceptBindingRequest` but accepts immediately (no payment gate)
- `SubmitLinkingRequestForm.tsx`: Placeholder only
- `AddressLinkingDetail.tsx`: May have binding flow

**Required Changes:**

#### File: `src/context/BindingContext.tsx`
**Change:** Add payment-gated binding flow
**Priority:** HIGH
```typescript
- Add: initiateBindingRequest(tnaId, subAddressId) → creates PENDING binding
- Add: processPayment(bindingId, paymentMethod) → payment gateway
- Add: verifyPayment(bindingId) → poll transaction status
- Add: activateBinding(bindingId) → only after PAID
- Modify: acceptBindingRequest to include payment check
```

### Flow 2: Safe Unlinking (Termination Protection)
**Blueprint Sequence:**
1. Trigger: User clicks "Terminate Binding"
2. In-Transit Check: `GET /v1/tna/{tna_code}/binding`
3. Logic Gate: Backend checks `shipments` table for `status = 'IN_TRANSIT'`
4. Error Handling: If in-transit exists → `409 Conflict`
5. Finalization: If no deliveries → `POST /v1/bindings/{id}/terminate`

**Current Implementation:**
- `UnlinkAddressModule.tsx`: Has UI for unlink but no in-transit check
- `BindingContext.tsx`: Has `toggleAutoAccept` but no terminate function
- No in-transit validation

**Required Changes:**
