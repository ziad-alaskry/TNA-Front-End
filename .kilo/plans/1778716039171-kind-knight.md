### Task 1: Header Logo Integration

#### 1-A. Remove Broken i18n Label
**Target:** Pages passing `header={t('common.roles.Visitor.overview')}` to AppShell

**Strategy:** The spec says to remove the element displaying this text from the header template. However, current Header component receives `title` prop which displays that text. Two approaches:

**Option A (Spec-compliant):** Remove title display logic from Header entirely, replace with logo
- Modify `Header.tsx` lines 77-82: remove `{title && <div>...{title}</div>}`
- Keep Breadcrumbs (lines 85-89) as the only left-side content
- This matches spec: header right side gets logo, left side keeps menu + breadcrumbs

**Option B (Minimal):** Keep title prop but pages stop passing it
- Would require updating ~70 page files to remove `header={...}` prop
- Higher risk, more changes

**Decision:** Follow **Option A** — Header should not render title div at all; breadcrumbs only. This matches spec §1-A "Remove this element from the header template entirely."

**Files to modify:**
- `tna-project/src/components/shell/Header.tsx` (remove title div, keep breadcrumbs)

#### 1-B. Insert Logo Link
**Position:** Right side of header, to the left of hamburger/menu button (end section, before balance chip or between language switcher and bell)

**Placement in end section order (left to right):**
Logo → Wallet Balance → Language Switcher → NotificationBell → UserAvatar

**Implementation:**
- Add `<Link href={logoHomeHref}>` with inline SVG from `logo-clean.svg`
- Compute `logoHomeHref` based on role (already have `rolePath` computed in Header)
- Need to add computed property or inline logic: `/visitor/home`, `/owner/home`, `/carrier/home`, `/gov/home`

**Files to modify:**
- `tna-project/src/components/shell/Header.tsx` (add logo link with inline SVG)

#### 2-D. Panel Positioning & Outside-click Dismissal
**Required changes:**

1. **Wrap bell in `.notif-wrapper`** (position: relative)
   - In Header: wrap `NotificationBell` in a `<div className="notif-wrapper">`
   
2. **Panel positioning** (NotificationPanel.tsx root):
   - Change from `fixed inset-0 flex justify-end` → `absolute` positioned within wrapper
   - Need to restructure: Panel should NOT be `fixed inset-0` anymore
   - New structure: Wrapper (relative) → Panel (absolute, right:0, top: calc(100% + 8px))

3. **Outside-click overlay:**
   - Add transparent `<div className="notif-click-outside" />` behind panel
   - `position: fixed; inset: 0; z-index: 1999; background: transparent`
   - Click closes panel

4. **Z-index layering:**
   - Overlay: `z-index: 1999`
   - Panel: `z-index: 2000`

5. **Entry animation:**
   ```css
   @keyframes notifPanelIn {
     from { opacity: 0; transform: translateY(-6px) scale(0.98); }
     to   { opacity: 1; transform: translateY(0)   scale(1); }
   }
   .notif-panel { animation: notifPanelIn 0.18s ease; }
   ```

**Critical architectural change:** NotificationPanel must no longer be a full-screen fixed overlay at the app root level. It needs to be positioned relative to the bell in the header.

**Current structure (AppShell.tsx line 147):**
```tsx
<NotificationPanel /> {/* Rendered at root, fixed inset-0 */}
```

**Required restructure:**
Option A: Move NotificationPanel into Header component, wrap with notif-wrapper
Option B: Keep NotificationPanel at root but use portal / absolute positioning relative to bell

**Simpler (Option A):**
1. Remove `<NotificationPanel />` from `AppShell.tsx`
2. Render `<NotificationPanel />` inside `Header.tsx`, wrapping bell in `.notif-wrapper`
3. Panel becomes sibling of bell within wrapper, uses absolute positioning

This matches spec §2-D: "Use absolute positioning relative to the bell wrapper."

**Files to modify:**
- `tna-project/src/components/layout/AppShell.tsx` (remove NotificationPanel render)
- `tna-project/src/components/shell/Header.tsx` (add notif-wrapper around bell, render NotificationPanel conditionally inside wrapper)
- `tna-project/src/components/ui/NotificationPanel.tsx` (change root to `absolute`, accept `isOpen` prop rather than reading store directly, OR keep store but restructure markup)

**Recommended:** Keep NotificationPanel as standalone UI component, but change it to accept `isOpen` prop and render conditionally in Header. Remove store dependency from component itself (state lifted to Header/AppShell).

Current: NotificationPanel reads `isNotificationPanelOpen` from store directly.
After change: Header reads store, passes `isOpen` prop to NotificationPanel.

- `notifications.markAllRead`
- `notifications.empty.title`
- `notifications.empty.subtitle`

**Current state:** `en.json` and `ar.json` have NO `notifications` key.

**Required:** Add these keys to both locale files.

**Per project process (OPTIMIZED_IMPLEMENTATION_PLAN.md §Task 3B):**
> "All notification strings should be added directly to `ar.json`/`en.json` using `i18n-apply-schema.js` as the merge tool."

**Procedure:**
1. Create `i18n-patch.json` with new keys:
   ```json

     "en": { "notifications": { "title": "Notifications", "markAllRead": "Mark all read", "empty": { "title": "No notifications", "subtitle": "You're all caught up!" } } },
   ```

2. Run `node scripts/i18n-apply-schema.js` to merge
3. Commit updated `ar.json` and `en.json`

**Files to modify:**
- `tna-project/public/locales/en.json` (via merge script)
- `tna-project/public/locales/ar.json` (via merge script)
